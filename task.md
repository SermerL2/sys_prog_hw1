Домашнее задание
Исследование Spatial Locality и структуры данных

Цель:
исследовать влияние пространственной локальности данных на производительность процессора.

Шаги выполнения:

Реализация двух способов обхода матрицы (Stride Access vs Sequential Access):

Неоптимальный вариант (по столбцам): напишите функцию вычисления L1-нормы (суммы абсолютных значений элементов по столбцам/строкам) для квадратной матрицы из элементов u64, выполняющую внешнее итерирование по столбцам, а внутреннее - по строкам.

Оптимальный вариант (по строкам): напишите аналогичную функцию вычисления L1-нормы, выполняющую обход строго последовательно по строкам (память читается подряд без прыжков).

Сбор аппаратных метрик под профайлером:

Запустите оба варианта под профилировщиком на выбор в зависимости от вашей ОС/CPU или предпочтений: perf (Linux), AMD uProf, Intel VTune или Instruments (macOS).

Снимите счётчики:

количество кэш-промахов L1 Data Cache;
показатель IPC (Instructions Per Cycle).

Аппаратное доказательство оптимальности:

Сведите полученные из профилировщика данные в итоговую таблицу.

Вычислительный расчёт: рассчитайте общее количество кэш-линий, которое считывается из памяти при обоих вариантах обхода, а также объём «бесполезно» прокачанного трафика оперативной памяти при обходе по столбцам из-за вытеснения незадействованных байт из 64-байтных кэш-линий. Приведите ссылку на официальную документацию вашей архитектуры, подтверждающую размер кэш-линии.

Вывод: на основе метрик профилировщика, расчётов и сторонней / официальной документации / бенчмарков (например, uops.info, Intel/AMD Software Optimization Guides) объясните, почему последовательный обход матрицы является оптимальным для вашего конкретного процессора (с учётом SIMD).

Формат сдачи: ссылка на публичный GitHub (или подобные сервисы) репозиторий.

Критерии оценки:
Статус «Принято», если:

Репозиторий содержит скрипты и описание сборки проекта.
Метрики «до» и «после» указаны в отчёте в README.md файле репозитория.
Аргументация оптимальности решения логична.
